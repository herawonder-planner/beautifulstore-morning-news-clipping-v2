# 뉴스 클리핑 · 기사 1건 요약

기사 1건을 읽고, 원문 근거가 붙은 3줄 요약을 마크다운 파일로 저장합니다.
톤은 차분하고 신뢰감 있게, 과장 없이 씁니다.
이 스킬은 요약 파일 저장까지만 합니다. 어떤 형태의 발송·공유도 하지 않습니다.

## 1. 입력 판별

- `http://` 또는 `https://`로 시작하는 URL: 실제 모드
- `samples/` 아래의 `.txt` 파일: 가상 모드
- "전날", "어제", `daily`: 전날 수집 모드(서울 기준 전날). 6절
- `daily YYYY-MM-DD`: 전날 수집 모드(지정한 날짜). 6절
- `routine`: 서울 기준 전날 daily 수집 + 시트 쌓기 + Gmail 임시보관함 초안. 9절
- `daily-virtual`: 가상 수집 모드. `samples/가상검색결과-2026-10-01.tsv`를 쓰고 Aside를 쓰지 않습니다. 6절
- 위 어느 것도 아니면 기사 URL, 샘플 파일 경로 또는 `daily`가 필요하다고 묻고 멈춥니다. (입력이 비어 있을 때도 같습니다.)
- 1건 모드(URL·샘플 .txt)의 동작은 2~5절 그대로이며 바뀌지 않았습니다.

## 2. 실제 모드

1. `mkdir -p output/raw`
2. 아래 명령을 실행합니다.
   `bash .claude/skills/news-clipping/read-article.sh "<URL>" "output/raw/article-snapshot.txt"`
3. 저장된 snapshot(접근성 트리)에서 다음을 찾습니다.
   - 제목: `heading "..." [level=1]`
   - 매체: 문서 title 끝의 ` - 매체명`
   - 발행일: 입력 또는 등록 일시(예: `입력 2026.10.08 09:51`)에서 날짜를 `YYYY-MM-DD`로
   - 본문: `text:` 블록의 문단들
4. 스크립트가 실패했거나, 제목 또는 본문이 없으면 접근 실패입니다.
   `templates/clipping-draft.md`의 접근 실패 블록 형식으로 `output/clipping-draft.md`를 저장하고, 요약하지 않습니다. 사유는 한 줄로 적습니다.
5. 정상이면 4절의 요약 규칙으로 `output/clipping-draft.md`를 저장합니다. 문서 안내 줄은 `> 담당자 검토 전 초안`입니다.

## 3. 가상 모드

- Aside를 쓰지 않고 샘플 파일을 읽어 같은 형식으로 `output/clipping-draft-virtual.md`에 저장합니다.
- 문서 안내 줄은 `> [가상 예시] 실제 보도 아님 · 담당자 검토 전 초안`으로 합니다.
- 제목·매체·발행일·URL은 샘플 파일의 값을 그대로 씁니다.
- `samples/` 아래 .txt 경로를 받았지만 파일이 없거나 비어 있으면 결과 파일을 만들지 않습니다. "샘플 파일을 찾을 수 없습니다: <경로>"라고 알리고 `samples/` 안의 .txt 목록을 보여 준 뒤 멈춥니다. 가상 내용을 지어내지 않습니다.

## 4. 파일 형식과 요약 규칙

형식은 `templates/clipping-draft.md`를 따릅니다.
순서: 문서 제목, 안내 줄, 기사 제목(`##`), 메타 표, `### 3줄 요약`.

- 문서 제목 `# 아름다운가게 뉴스 클리핑 초안 · YYYY-MM-DD`의 날짜는 서울 기준 오늘이며 `TZ=UTC-9 date '+%Y-%m-%d'` 결과를 씁니다.
- 읽은 시각은 `TZ=UTC-9 date '+%Y-%m-%d %H:%M'` 결과를 씁니다.
- POSIX 표기라 UTC-9가 서울(UTC+9)입니다. 이 PC의 Git Bash에는 tzdata가 없어 `Asia/Seoul` 이름을 쓰면 UTC 시각이 나옵니다.
- 메타 표: 상태(`원문 확인`) / 매체 / 발행일 / URL / 읽은 시각(서울)
- 요약은 3줄이고 한 줄에 한 문장입니다.
- 원문에 있는 사실만 씁니다. 수치는 원문 그대로 쓰고, 평가와 추측은 쓰지 않습니다.
- 광고, 관련 기사, 많이 본 뉴스, 댓글 영역은 본문으로 보지 않습니다.
- 각 요약 줄 아래에 `- 근거: "원문 인용" (n문단)`을 붙입니다.
  - 인용은 원문 문장을 그대로 따옴표로 옮깁니다. 60자 안팎으로 발췌할 수 있지만 단어를 바꾸지 않습니다.
  - 문단 번호는 사진 설명을 제외한 본문 문단을 1부터 센 값입니다.

## 5. 저장 후 안내

사용자에게 다음을 보여 줍니다.

- 저장한 파일 경로
- 메타 표
- 3줄 요약과 근거
- "원문 대조는 담당자가 확인해 주세요."
- 이 파일은 초안이며, 외부 발송이나 공유는 하지 않았다는 점

## 6. 전날 수집 모드 (daily / daily-virtual)

기준일 안의 '아름다운가게' 기사를 모아 기사별 3줄 요약 초안과 수집 CSV를 만듭니다.
요약은 이 스킬을 실행한 Claude가 한 번에 판단해 씁니다. 별도 역할이나 병렬 작업은 쓰지 않습니다.

### 6-1. 기준일과 폴더

- 기준일: "전날"·"어제"·`daily`는 `TZ=UTC-9 date -d 'yesterday' '+%Y-%m-%d'` 결과, `daily YYYY-MM-DD`는 입력한 날짜
- 작성 시각: `TZ=UTC-9 date '+%Y-%m-%d %H:%M'` (서울)
- 결과 폴더: `output/YYYY-MM-DD/` (기준일)
- 폴더가 이미 있으면 "output/YYYY-MM-DD/가 이미 있어 덮어씁니다"라고 알린 뒤 덮어씁니다. 메일 초안은 같은 날 다시 만들면 Gmail 임시보관함에 중복될 수 있습니다.
- 파일
  - `search-results.tsv`: 검색 결과 (열: press, title, url, snippet)
  - `raw/NN-snapshot.txt`: 기사 원문 snapshot (순번 두 자리: 01, 02 …)
  - `collection.csv`: 수집 기록 (UTF-8 BOM)
  - `clipping-draft.md`: 요약 초안

### 6-2. 수집 절차 (daily)

1. `mkdir -p output/YYYY-MM-DD/raw`
2. `bash .claude/skills/news-clipping/search-news.sh YYYY-MM-DD output/YYYY-MM-DD/search-results.tsv`
   - 실패(종료코드 0이 아님)하면 `clipping-draft.md`에 `## 수집 실패`와 사유 한 줄만 쓰고 요약하지 않습니다. 형식은 `templates/daily-clipping.md`의 수집 실패 블록입니다.
   - 0건이면 `## 수집 결과: 0건`과 "기준일에 '아름다운가게' 기사가 검색되지 않았습니다. 가상 기사로 대체하지 않았습니다."를 씁니다. 가상 기사로 채우지 않습니다.
3. 검색 결과를 위에서부터 순번을 매겨 기사마다 `bash .claude/skills/news-clipping/read-article.sh "<URL>" "output/YYYY-MM-DD/raw/NN-snapshot.txt"`를 1건씩 실행합니다.
   - 스크립트가 실패하거나 제목 또는 본문이 없으면 상태 `접근 실패`로 기록하고, 사유를 비고에 적습니다.
4. 읽은 기사마다 판정합니다.
   - 제목 또는 본문에 '아름다운가게'(띄어쓰기 없음)가 없으면 `제외-키워드 불일치`입니다. ('아름다운 동행가게', '아름다운 한글길' 같은 경우)
   - 같은 행사를 다룬 다른 기사가 이미 있으면 `중복`입니다. 가장 먼저 읽은 기사를 대표로 하고, 비고에 `대표: 매체명`을 적습니다. 같은 URL이 겹친 경우도 중복입니다.
   - 나머지는 `원문 확인`입니다.
5. 발행일(`YYYY-MM-DD`)이 기준일과 다르면 비고에 "발행일이 기준일과 다름"을 적고, 요약은 하되 초안의 메타 표 발행일 옆에도 `(기준일과 다름)`을 표시합니다.

### 6-3. 가상 수집 (daily-virtual)

- Aside와 search-news.sh를 쓰지 않고 `samples/가상검색결과-2026-10-01.tsv`를 `search-results.tsv`로 쓰며, 기준일은 파일명의 `2026-10-01`입니다.
- 폴더는 `output/virtual-2026-10-01/`로 하고 6-1의 파일을 같은 이름으로 만듭니다. (`raw/`는 만들지 않습니다.)
- 기사 본문
  - `https://example.com/news/virtual-001`: `samples/가상기사-되살림터-개소.txt`
  - `https://example.com/news/virtual-404`: 접근 실패로 처리합니다.
  - 그 밖의 가상 URL: TSV의 snippet만으로 키워드를 확인합니다.
- 초안 맨 위 안내 줄은 `> [가상 예시] 실제 보도 아님 · 담당자 검토 전 초안 · 작성 YYYY-MM-DD HH:MM(서울)`입니다.
- 메일 초안은 만들지 않습니다.

### 6-4. collection.csv

- 인코딩은 UTF-8 BOM, 열은 `순번,기준일,매체,제목,발행일,URL,상태,비고`입니다.
- 상태는 `원문 확인` / `접근 실패` / `제외-키워드 불일치` / `중복` 중 하나입니다.
- 쉼표·따옴표·줄바꿈이 있는 값은 큰따옴표로 감싸고 안의 큰따옴표는 두 번 씁니다.
- 접근 실패 기사는 발행일을 비워 둡니다.

### 6-5. clipping-draft.md

형식은 `templates/daily-clipping.md`를 따릅니다.

- 문서 제목 `# 아름다운가게 뉴스 클리핑 초안 · 기준일 YYYY-MM-DD`, 안내 줄 `> 담당자 검토 전 초안 · 작성 YYYY-MM-DD HH:MM(서울)`
- `## 수집 요약` 표: 검색 결과 / 원문 확인 / 접근 실패 / 제외(키워드 불일치) / 중복 건수. 합이 검색 결과 건수와 같아야 합니다.
- `원문 확인` 기사마다 시안 B 블록(`## 제목`, 메타 표, `### 3줄 요약`)을 씁니다. 요약 규칙은 4절과 같습니다.
  - 요약은 3줄, 한 줄 한 문장, 원문에 있는 사실만 씁니다.
  - 각 줄 아래 `- 근거: "원문 인용" (n문단)`을 붙이고, 인용은 단어를 바꾸지 않습니다. 문단 번호는 사진 설명을 제외한 본문 문단 기준입니다.
  - 중복 기사의 매체는 대표 기사 메타 표 아래에 `같은 내용 보도: 매체A, 매체B` 한 줄로 씁니다. 중복 기사는 요약하지 않습니다.
- 마지막에 `## 요약하지 않은 기사` 표(매체 / 제목 / URL / 사유)를 씁니다. 사유는 `접근 실패`, `키워드 불일치`, `중복(대표: 매체명)`입니다. 해당 기사가 없으면 이 절을 생략합니다.

### 6-6. sheet-rows.tsv

- 파일: `output/YYYY-MM-DD/sheet-rows.tsv` (헤더 없는 탭 구분 12열, UTF-8). `collection.csv`와 `clipping-draft.md`에서 만듭니다.
- 열 순서: 수집일시(서울) / 기준일 / 순번 / 매체 / 제목 / 발행일 / URL / 상태 / 요약 1 / 요약 2 / 요약 3 / 비고
- 기사 1건당 1행입니다. 수집일시는 초안의 작성 시각입니다.
- 상태가 `원문 확인`이면 요약 1~3에 초안의 3줄 요약 문장을 넣고, 그 밖의 상태는 요약 칸을 비웁니다. (근거 줄은 넣지 않습니다.)
- 값 안의 탭과 줄바꿈은 공백으로 바꿉니다. 열이 비어도 탭 12열을 맞춥니다.
- 0건 또는 수집 실패인 날은 행 1개입니다. 매체·제목은 빈 칸, 상태는 `0건` 또는 `수집 실패`, 비고에 사유를 적습니다.
- 시트에 쌓는 일은 9절 루틴이나 사용자가 요청했을 때만 합니다.

## 7. Gmail 임시보관함 초안

사용자가 메일 초안을 요청했거나 루틴 요청일 때만 만듭니다. 요청이 없으면 만들지 않습니다. 가상 수집 모드에서는 만들지 않습니다.
이 스킬은 어떤 경우에도 메일을 발송하지 않습니다. 발송은 담당자가 Gmail에서 직접 합니다.

1. 6절을 먼저 끝냅니다.
2. 수신: `config.local.env`의 `CLIP_MAIL_TO` 값
3. 제목: `[아름다운가게 뉴스 클리핑] 기준일 YYYY-MM-DD · 원문 확인 n건 (검토 전 초안)` (큰따옴표·작은따옴표·역슬래시는 쓰지 않습니다.)
4. `bash .claude/skills/news-clipping/make-mail-html.sh "output/YYYY-MM-DD/clipping-draft.md" "output/YYYY-MM-DD/mail-draft.html"`로 본문 HTML을 만듭니다. (제목 색은 primary `#2D5A27`, 표는 머리 행 `th`와 값 행 `td`로 변환됩니다.)
5. `bash .claude/skills/news-clipping/create-gmail-draft.sh "$CLIP_MAIL_TO" "<제목>" "output/YYYY-MM-DD/mail-draft.html" "output/YYYY-MM-DD/mail-draft-log.md"`
6. 종료코드 0이면 "Gmail 임시보관함 저장을 확인했습니다(작성 창 표시 기준)"라고 알립니다. 작성 창에 `임시보관함에 저장됨`이 보이는 것을 기준으로 하며, 보이지 않으면 `in:drafts` 검색으로 보조 확인합니다. 0이 아니면 실패 사유(종료코드 5는 "임시보관함에서 초안을 찾지 못함")를 알리고, Gmail 임시보관함을 직접 확인해 달라고 안내합니다.
7. 0건이거나 수집 실패여도 그 사실을 담은 초안을 만듭니다.
8. 로그(`mail-draft-log.md`)에는 시각(서울)·수신자·제목·결과·threadId가 남습니다. 같은 기준일을 다시 실행하면 초안이 중복될 수 있다는 안내도 로그에 있습니다.

## 8. 수집 후 안내

사용자에게 다음을 보여 줍니다.

- 저장한 폴더와 파일 경로, 수집 요약 표(건수)
- 요약하지 않은 기사와 사유
- 메일 초안을 만들었다면 Gmail 임시보관함에서 확인하라는 안내와 "발송은 담당자가 Gmail에서 직접 합니다"
- "원문 대조는 담당자가 확인해 주세요."

## 9. 매일 아침 8시 루틴 (routine)

`routine`은 서울 기준 전날을 대상으로 수집, 시트 쌓기, Gmail 임시보관함 초안을 순서대로 합니다.

- 기본 시트: 문서 '2026 뉴스클리핑', 주소는 `config.local.env`의 `CLIP_SHEET_URL`
- 시트 기준: 첫 시트(gid 0), 계정은 `CLIP_GOOGLE_ACCOUNT`(uid는 `CLIP_GOOGLE_UID`), 열 순서는 6-6과 같고 헤더는 비어 있을 때 한 번만 씁니다.

순서

1. 6절로 수집하고 `clipping-draft.md`, `collection.csv`를 만듭니다. 기사 읽기는 1건씩 순차로 합니다. 전체 실행 시간이 길 수 있습니다.
2. 6-6으로 `sheet-rows.tsv`를 만듭니다.
3. `bash .claude/skills/news-clipping/append-to-sheet.sh "$CLIP_SHEET_URL" "output/YYYY-MM-DD/sheet-rows.tsv" "YYYY-MM-DD"`
   - 종료코드 0: 쌓았다고 기록합니다.
   - 종료코드 6: 이미 쌓인 기준일이라고 알리고 건너뜁니다. 사용자가 다시 쓰라고 명시한 경우에만 `--force`를 붙입니다.
   - 종료코드 7 또는 그 밖: 실패 단계(stderr)를 기록합니다.
4. 7절로 메일 초안을 만듭니다. 요약 줄에 시트 링크를 포함합니다. 0건·수집 실패인 날도 만듭니다.
5. 마지막에 각 단계 결과(성공 / 건너뜀 / 실패 사유)를 5줄 이내로 요약해 보여 줍니다.

규칙

- 한 단계가 실패해도 다음 단계는 이어가되, 실패를 요약에서 분명히 표시합니다. (수집이 실패하면 0건·수집 실패 행과 그 사실을 담은 메일 초안을 만듭니다.)
- 어떤 경우에도 메일을 발송하거나 공유하지 않습니다. 발송은 담당자가 Gmail에서 직접 합니다.
- 쓰기 대상은 `output/YYYY-MM-DD/` 폴더, 위 시트 한 곳, Gmail 임시보관함 초안뿐입니다. 그 밖의 파일·시트·문서·채널에는 쓰지 않습니다.
- 예약 실행에 쓰는 프롬프트는 `routine/daily-8am.md`입니다.

## 10. 설정 파일 (config.local.env)

메일 수신 주소, 시트 주소, Google 계정은 코드나 문서에 적지 않고 `config.local.env`에서 읽습니다. 이 파일은 GitHub에 올라가지 않습니다.

- 항목: `CLIP_MAIL_TO`(수신 주소), `CLIP_SHEET_URL`(시트 주소), `CLIP_GOOGLE_ACCOUNT`(Aside에 로그인한 Google 계정), `CLIP_GOOGLE_UID`(그 계정의 번호, 기본 0)
- 메일 초안(7절)과 시트 쌓기(6-6, 9절)를 하기 전에 한 번 읽습니다: `set -a; . ./config.local.env; set +a`
- 명령은 `"$CLIP_MAIL_TO"`, `"$CLIP_SHEET_URL"`처럼 변수로 씁니다. 사용자에게 값을 보여 줄 때도 주소 전체는 적지 않고 "설정 파일의 수신 주소"처럼 말합니다.
- 파일이 없거나 해당 값이 비어 있으면 그 단계(메일 또는 시트)를 실패로 기록하고, `config.example.env`를 `config.local.env`로 복사해 값을 채우라고 안내합니다. 수집(6절)은 설정 없이도 진행합니다.
- 시트 쌓기: `bash .claude/skills/news-clipping/append-to-sheet.sh "$CLIP_SHEET_URL" "output/YYYY-MM-DD/sheet-rows.tsv" "YYYY-MM-DD"`
